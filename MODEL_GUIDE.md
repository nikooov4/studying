# Модели для обучения

Рабочая схема от **02.10.2026**. Основная модель — **GPT-6.1 Sol / Medium** (`gpt-6.1-sol`), заменяет GPT-5.6 Terra. Простое повторение — **GPT-6 Luna / Low**. Сложная проверка — **Sol High**; **GPT-6 Astra High** только для особой эскалации.

Качество проверяем по объяснениям, коду и результатам запуска. Одинаковое качество и конкретную экономию заранее не гарантируем. Рекомендации действуют при доступности моделей в интерфейсе.

| Этап | Рекомендация |
|---|---|
| Простое повторение проверенных фактов | GPT-6 Luna Low; можно остаться на Sol ради непрерывности |
| Recall с анализом кода, новой ошибкой или неоднозначным объяснением | GPT-6.1 Sol Medium |
| Новая теория, мини-практика, обычное ревью Go/SQL | GPT-6.1 Sol Medium |
| Самостоятельное написание решения | Ждать сообщения ученика, без фоновых вызовов |
| Easy и обычные Medium с понятной корректностью | GPT-6.1 Sol Medium |
| Сложное доказательство, нетривиальная ошибка, race/deadlock, конкурентные транзакции | GPT-6.1 Sol High |
| Полный технический mock и защита проекта | GPT-6.1 Sol High |
| Существенная неоднозначность после Sol High/XHigh, особенно сложный независимый разбор | GPT-6 Astra High |

- День 7: Sol High для контрольного интервью Go Core; обычные алгоритмы и разбор ошибок — Medium.
- Дни 8–13: Sol Medium для основ concurrency; High для сложных interleaving, race/deadlock и спорного ревью.
- День 14: Sol High для обоих mock.
- Дни 15–28: Sol Medium; High для сложных cancellation/leaks, сетевых ошибок, изоляции транзакций и неоднозначных планов запросов.
- Дни 29–47: Sol Medium для локальных вопросов; High для ревью архитектуры, инвариантов, атомарности, идемпотентности и итоговой защиты проектов.
- Дни 48–49: Sol High для timed algorithms и Go Platform проверки.
- Дни 50–55: Sol Medium для обычных вопросов; High для сложного проектирования и интеграционных рисков.
- День 56: Sol High для защиты архитектуры.
- Дни 57–63: Sol High для mock и защиты; между ними Medium или Luna Low для простого recall.

Выбор определяется конкретным этапом и сложностью. Не открывать новый диалог для каждого короткого блока и не переключаться на каждый вопрос.

## Luna и самостоятельная практика

Luna подходит для однозначных вопросов по изученным фактам, форматирования учебных записей и поиска очевидных мест в файлах. Новая теория, объяснение причин или анализ ошибки — Sol Medium.

Выбор модели не меняет запрет писать решения за ученика. Генерация тестов, преобразования кода, комментарии, конфигурация и механические исправления не выполняются наставником, если являются предметом упражнения. Ученик сам пишет и исправляет решение; наставник проверяет и подсказывает. Служебные записи можно обновлять по AGENTS.md.

## Reasoning и эскалация

Medium — по умолчанию. High — при противоречии прогнозу/запуску/документации, конфликтующих объяснениях, сложном доказательстве корректности, ошибке нескольких goroutine, race/deadlock, конкурентных транзакциях, неоднозначном SQL-плане/изоляции, комплексном архитектурном ревью или полноценном интервью. Простая ошибка ученика и простое обоснование алгоритма сами по себе не требуют High.

XHigh — если High не дал надёжного объяснения или нужен длинный многошаговый анализ. Astra High — если Sol High/XHigh не разрешил существенную неоднозначность либо нужен особо глубокий независимый разбор нескольких подсистем, конкурентной модели, доказательства или архитектурных альтернатив. Важность задачи сама по себе не повод выбирать Astra.

Перед эскалацией сохранить конкретную проблему, релевантный код, проверки и противоречия; не передавать весь диалог без необходимости. Дополнительных агентов ради экономии не запускать.

## Старые модели и переключение

GPT-6 Sol обычно не выбирать при доступном GPT-6.1 Sol без специфической причины. GPT-5.6 Terra/Sol — fallback при недоступности основной модели; GPT-5.6 Luna — при недоступности GPT-6 Luna. Доступность уточнять по интерфейсу; старую модель не считать равнозначной заменой автоматически.

Наставник рекомендует модель и reasoning, пользователь переключает в интерфейсе. Изменение AGENTS.md само модель не переключает. В текущем наборе инструментов команды смены основной модели нет; глобальные настройки не меняются.
