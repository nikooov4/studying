# Модели для обучения

Рабочая схема от 11.09.2026. Основной выбор — **GPT-5.6 Terra / Medium**. Качество проверяем по конкретным ответам, объяснениям и коду; отсутствие потерь качества заранее не гарантируется. Названия ниже применяются, если модели доступны в интерфейсе пользователя.

| Этап | Рекомендация |
|---|---|
| Простое повторение ранее проверенных фактов | Luna Low; можно остаться на Terra ради удобства |
| Recall с анализом кода, новой ошибкой или неоднозначным объяснением | Terra Medium |
| Новая теория, мини-практика, обычное ревью Go/SQL | Terra Medium |
| Самостоятельное написание решения | Ожидание сообщения ученика, без фоновых вызовов |
| Easy и обычные Medium с понятной корректностью | Terra Medium |
| Сложное доказательство, нетривиальная ошибка, race/deadlock, конкурентные транзакции | Sol Medium |
| Полный Avito/Go Platform/SQL/алгоритмический mock, защита проекта | Sol Medium |

## Привязка к дням STUDY_PLAN.md

- Дни 1–6: Terra Medium; Luna только для простого повторения.
- День 7: Sol Medium для контрольного интервью Go Core; обычные алгоритмы можно разбирать на Terra.
- Дни 8–13: Terra Medium для основ concurrency; Sol Medium для сложных interleaving, race/deadlock и спорного ревью.
- День 14: Sol Medium для обоих mock.
- Дни 15–28: Terra Medium; Sol Medium для сложных отмен/leaks, сетевых ошибок, изоляции транзакций и неоднозначных планов запросов.
- Дни 29–47: Terra Medium для локальных вопросов; Sol Medium для ревью архитектуры, инвариантов, атомарности, идемпотентности и итоговой защиты каждого проекта.
- Дни 48–49: Sol Medium для timed algorithms и Go Platform проверки.
- Дни 50–55: Terra Medium для обычных вопросов; Sol Medium для проектирования и интеграционных рисков.
- День 56: Sol Medium для защиты архитектуры.
- Дни 57–63: Sol Medium для mock и защиты; повторение между ними можно проводить на Terra.

Внутри дня выбор определяется этапом. Не нужно открывать новый диалог для каждого короткого блока или переключать модель на каждый вопрос.

## Когда рекомендовать Sol

Если вывод противоречит запуску/документации, два объяснения наставника противоречат друг другу, не удаётся обосновать корректность либо ошибка затрагивает несколько goroutine/транзакций — сохранить конкретный вопрос и предложить Sol Medium. Простая ошибка ученика сама по себе не требует дорогой модели. Не выдавать непроверенный ответ как окончательный. High использовать только при сохраняющейся сложности, не по умолчанию.

## Переключение и учёт расхода

Наставник рекомендует модель, пользователь выбирает её в интерфейсе. В текущем наборе инструментов нет команды переключения модели основного диалога. Изменение AGENTS.md не выполняет переключение. Глобальные настройки не меняются.

Стоимость API и расход лимитов подписки Codex — разные показатели: не переносить соотношение API-цен на лимиты аккаунта и не обещать конкретный процент экономии. Более дешёвая модель не обязательно генерирует меньше токенов. Уменьшение ненужного контекста и повторных вызовов — отдельная мера.

Основание для общего позиционирования моделей: [официальный каталог OpenAI](https://developers.openai.com/api/docs/models) (Terra — баланс качества и стоимости, Luna — экономичные массовые задачи, Sol — сложная профессиональная работа). Распределение по учебным дням — рекомендация для этого проекта, не результат сравнительного тестирования наставников.
