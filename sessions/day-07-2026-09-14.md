## Результаты и ошибки

- Recall: ученик сначала назвал импорт достаточным условием для доступа к `newClient` из другого пакета. Уточнено: импорт не меняет visibility; из другого пакета доступны только экспортируемые идентификаторы с заглавной буквы, например `NewClient`. Внутри того же пакета регистр не ограничивает доступ.
- Recall: верно предсказал вывод `1` для `defer fmt.Println(x)` при последующем `x = 2`; объяснил, что значение аргумента сохраняется в момент `defer`.
- Go Core — slices: ученик верно определил результат `[0 0 10 20 30]` и `len == 5`, но ошибочно указал `cap == 5`. Уточнено: нужна новая backing array, так как исходной ёмкости 4 не хватает; гарантируется лишь `cap >= 5`, конкретный рост не является контрактом языка.
- Go Core — slices: после подсказки верно объяснил выделение новой backing array: прежней `cap` не хватает для пятого элемента.
- Go Core — maps: верно предсказал `0 false` при comma-ok чтении отсутствующего ключа. Уточнено: `ok` отличает отсутствие ключа от существующего ключа со значением `0`.
- Go Core — pointers: верно предсказал вывод `5`; объяснил, что локальное переназначение параметра-указателя не меняет `n` у вызывающего кода. Уточнено: параметры в Go передаются по значению.
- Go Core — interfaces: сначала ошибочно признал `Counter{}` реализацией интерфейса при методе `Inc` на `*Counter`. После уточнения верно написал `var _ Incrementer = &Counter{}` и подтвердил роль pointer receiver в method set.
- Go Core — errors: верно объяснил, что `errors.Is` найдёт `ErrNotFound` после `fmt.Errorf` с `%w` в цепочке обёрток.
- Контроль Go Core завершён. Слабые точки: точное поведение роста `cap` после `append` и method set value vs pointer receiver; назначить повторение.
