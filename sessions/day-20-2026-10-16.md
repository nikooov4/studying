## Результаты и ошибки

- Самостоятельно объяснил: MaxIdleConns ограничивает свободные соединения для всех серверов, не активные запросы; активная передача не ограничивается IdleConnTimeout; return из анонимной функции завершает только её вызов, цикл продолжает следующую итерацию.
- Уточнения теории: IdleConnTimeout принадлежит клиентскому Transport, а не серверу; Client.Timeout охватывает обмен целиком, включая редиректы и чтение Body. Общий Transport означает общий пул, но не гарантирует одно TCP-соединение.
- Connection reuse потребовал подсказок: сначала общий клиент считался гарантией того же TCP, затем назван только Close; в итоге ученик ответил «дочитать до конца и закрыть». Наставник исправил свою категоричную формулировку: актуальный Go может дочитать ограниченный остаток при Close, но это не универсальная гарантия.
- Мини-практика: сначала собственные type вместо экземпляров, поля библиотеки использовались как типы; дан пример &Book на другом материале. Затем исправлены объекты Client/Transport, time.Second; MaxConnsPerHost заменён учеником на MaxIdleConnsPerHost.
- Backend: сначала ошибки только логировались, выполнение продолжалось к потенциально nil resp; defer в main закрывал тела лишь после цикла. Затем короткая анонимная функция закрывала Body до ReadAll. Ученик самостоятельно расширил её границы на Do/проверку err/чтение/вывод; теперь тело закрывается до следующей итерации, включая ранний выход при ошибке чтения.
- Self-check принят: при ошибке Do на третьей итерации return завершает только вызов анонимной функции, цикл переходит к четвёртой; ученик объяснил это самостоятельно.
- Готовый HTTP-код и учебные тесты наставник не писал, код ученика не исправлял.
