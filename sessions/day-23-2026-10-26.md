### SQL №7

Условие: пользователи без единого объявления дороже 1000, в том числе без объявлений и с одними дешёвыми/NULL-ценами. Город необязателен; колонки user_id,user_name,city_name; сортировка user_id ASC. Только JOIN, без подзапросов.

Ошибки: отбор дешёвых объявлений вместо отсутствия дорогих; представление, будто дорогое объявление отменяет совпадение с дешёвым; перенос фильтра в ON без отбора результата; IS NOT NULL вместо проверки отсутствия; неверные имена города и алиасы. После подсказок ученик сам собрал корректный запрос: LEFT JOIN cities, LEFT JOIN ads с условием ads.price>1000 в ON, затем WHERE ads.price IS NULL. Здесь NULL-проверка цены допустима: совпавшее объявление заведомо имеет ненулевую цену.

Ученик объяснил исключение пользователя с объявлением за 2000 и верно ответил: NULL > 1000 даёт UNKNOWN, такое объявление не совпадает в ON. №7 принят. Альтернатива NOT EXISTS обсуждалась только словами, без готового SQL.

### SQL №8

Условие: все категории с их объявлениями с ценой >=2000; категории без подходящих объявлений сохранить, объявления без продавца тоже сохранить. Колонки category_id,category_name,ad_id,title,price,seller_name. Сортировка category_id ASC,ad_id ASC NULLS LAST. Один SQL с JOIN без подзапросов.

Первая версия: LEFT JOIN ads и users, но WHERE ads.price>=2000 удалял категории без подходящих объявлений. Затем ученик перенёс схему отсутствия из №7: цена <2000 в ON и WHERE ads.price IS NULL. Разобран контрпример объявления за 2500: оно не совпадает, а результат ошибочно содержит NULL вместо данных объявления. Ученик выбрал 2500 среди 500/2500 и понял, что IS NULL отбрасывает присоединённое дорогое объявление.

Ученик сообщил о непонимании; попытку перейти к аналогии с отделами остановил, попросив разбирать сам запрос. Объяснение на отделах не было проведено. По таблице ожидаемых результатов разобрано различие целей №7 и №8. После этого ученик самостоятельно изменил порог на >=2000 и убрал WHERE; затем исправил adas на ads. Последняя версия полностью корректна по тексту: FROM categories LEFT JOIN ads по category_id и ads.price>=2000, LEFT JOIN users по seller_id, нужные колонки и сортировка. До окончательного зачёта ожидается объяснение случая продавца NULL.
